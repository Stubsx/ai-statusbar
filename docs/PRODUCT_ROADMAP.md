更新日期：2026-09-11
状态：P0、P1、P2 的本轮功能已全部实施并完成本地验证，已安装运行。没有公开发布或自动安装第三方扩展。

## 产品目标

帮助同时使用多个 AI 工具的用户减少主动检查进度的次数，在需要接手时及时回到原工具。保持轻量、原生、本地优先；菜单栏、浮球、桌宠和状态速览共享状态事实。

本轮基于实现与界面核对，尚未做真实用户研究。优先处理可信事件、找回任务、诊断原因，再补齐提醒、使用引导和生态贡献路径。阶段不绑定公开版本号。

## 关键产品语义

- 「本轮已结束，可查看结果」仅说明收到明确结束信号，不代表业务任务成功或结果正确。
- 中断、等待回答、采集错误独立处理；一般未返回工具调用和长时间无输出不能证明等待审批。
- 普通活动推断不会触发桌宠庆祝，也不会进入待处理列表。
- 历史、事件接口留在本机；现有多设备同步继续只同步用量。
- 功能默认值：事件导出、标题导出、配额提醒、登录启动均关闭；任务通知保持已有用户选择，权限按需申请。

## 支持边界

完整支持矩阵见 [TOOLS.md](TOOLS.md)，贡献规范见 [ADAPTERS.md](ADAPTERS.md)。

1. 初始明确事件覆盖 Codex App/CLI、Claude Code、ZCode；其他工具仍支持活动与用量。没有为不明来源的审批/失败状态伪造信号。
2. 当前跳转至应用、宿主终端/编辑器或 DSH 默认本机页面，不宣称精确定位某个会话窗口。tmux、后台运行和非默认 Web 端口需要手动定位。
3. 本地轮询不能保证看到两次采集之间被后续回合覆盖的每个事件；首次接入或采集恢复建立基线，不回放旧通知。历史不是审计日志。
4. 素材库是随 App 打包的轻量目录，目前有原创蓝点模板；不包含远程商店、社区账号、支付或第三方可执行插件。
5. 更新功能是用户主动检查与可信发布页入口；自动安装、Developer ID 公证、远程推送和团队共享未纳入本轮交付。
6. 登录启动使用 macOS 13+ SMAppService；macOS 12 用本机 LaunchAgent。自动测试不修改真实登录项或新增通知/录屏授权。

## 收敛为轻量伴随工具（2026-09-11）

用户反馈任务看板过大，因此默认界面改为状态速览：去掉五个常驻页签、全局展开按钮和多张待处理卡片。每个工具只显示一条当前任务；有提醒时只显示优先级最高的一条，其余通过数量入口打开记录。空闲工具不再展示历史任务标题，最多显示 4 个工具（有提醒或采集异常时最多 3 个），溢出工具在运行详情中查看。

用量、配额、活跃、历史和运行详情保留在右上角菜单；默认宽 300 点，历史/统计宽 340 点，主动打开的运行详情宽 380 点。首次打开默认速览；浮球、桌宠与菜单普通打开会恢复上次使用的页面及对应宽度，并跨应用重启保留。后端事件、通知、采集、隐私和素材功能保持原有能力。

收敛验证：原生截图覆盖空闲、忙碌、提醒、浅深色、隐私、采集异常和 8 工具 / 240 任务。相同的 7 任务 / 3 提醒场景从 340 × 524 点缩到约 300 × 223 点；压力场景与异常提示同时出现时约 300 × 333 点。统计、历史和详情按实际内容收高，内容区最高 320 点，超出后滚动。

本轮 Mac 处于锁定状态，交互使用隔离的原生窗口测试：⌘1–⌘5、⌘E 与 Esc 的路由及切页后的尺寸变化；通知策略仍通过隔离接收器验证。锁定桌面上的菜单鼠标操作未复测。

收敛版已构建并安装为 1.2.0（内部构建 115），App 与采集器均为 arm64 / x86_64，严格签名校验通过，证书与原安装一致。启动后确认进程存活并生成新的采集快照；收敛前的安装包保存在忽略目录 `output/compact-install-backup/`。全量开源检查、浮球 1681 个几何样本、22 个原生截图场景和 8 次原生快捷键/尺寸检查均通过。

## 事件点击与已读（2026-09-11）

事件点击原来只跳转，未调用已读逻辑；等待事件即使已读也持续计入提醒，导致用户无法清除。现将提醒已读与任务状态分开：速览、历史和系统通知共用已读处理；点击事件即清除该次提醒、更新浮球/桌宠/菜单栏角标，保留历史。等待事件已读后仍记录等待状态，不代替用户回答或授权。相同事件重采集、重启不再恢复未读；同会话的新事件继续提醒。

批量通知只标记其事件 ID 对应的记录，保留随后到来的新事件；配额通知不影响任务未读。用户在一秒合并窗口内查看的事件会从待发通知中移除，避免刚看完又弹出。历史中的勾选按钮也可单独标记等待提醒已读。

事件已读验证：70 条事件/配额断言通过，覆盖等待提醒的读取、重复采集、重启持久化和同会话的新事件；隔离原生窗口验证共享点击动作、单条/批量/配额通知的读取范围、待发通知取消，并生成点击前后截图。原有检查与 24 个原生截图场景通过。

事件已读修复版已安装为 1.2.0（内部构建 116），签名身份保持一致，启动后采集正常，设置 JSON 的内容经规范化比较一致。实机通过速览点击一条本项目事件后，未读数从 6 降为 5；在最近事件中确认原记录保留且标记已读，再返回速览仍为 5。历史宿主已退出时显示原有提示，已读状态仍保留。此次只标记了所点击的一条事件，没有批量清空其他记录。

## 小范围试用后验证

不新增默认遥测，通过自愿反馈观察：主动切窗口次数是否下降、提醒后回到任务的操作数、每天误提醒/重复提醒/漏提醒、首次接入成功率和一周常驻意愿。根据这些反馈再决定是否扩展精确跳转、更多明确事件、远程目录和自动更新。


## 状态栏跳转与窗口恢复（2026-09-12）

状态栏菜单里的工具名称现在可直接点击。统一跳转路由优先按应用标识识别 Codex、Kimi、ZCode 与 Hermes；已运行的应用和 CLI 宿主通过 Launch Services 的重开请求恢复窗口，明确要求前台激活并复用原实例。macOS 14 及以上先让出激活权；隐藏应用先取消隐藏，系统打开失败再尝试直接激活，仍失败则显示反馈。

Kimi CLI 补齐 kimi-code 名称和 Python 包装进程识别，Codex 等支持常见 Node 包装进程；排除任务正文中的假匹配和桌面应用内置服务。只有一个宿主应用时直接打开，多个宿主才显示选择。具体会话窗口或终端标签仍取决于宿主能力。

构建 120 已使用原 Lingmou Local 签名安装。验证包括 12 个正反 CLI 路由用例、24 张隔离原生界面截图、8 个键盘导航场景及现有事件已读与通知管道检查。实机从灵眸面板点击 Codex 后，独立读取系统前台应用为 Codex；ZCode 最小化后可见窗口数从 0 恢复为 1，隐藏后从 hidden=true 恢复为 false，均成为前台应用并保持原进程。前台状态在再次选择目标应用之前读取，避免验证工具自行激活造成误判。此次未逐一验证所有第三方应用版本的重开行为。


## Codex 本地对话直达（2026-09-12）

OpenAI 官方命令文档明确支持 `codex://threads/<thread-id>`。构建 121 将当前任务、最近任务、事件记录和单条通知的会话 ID 交给统一路由，通过指定 Codex 应用的系统 URL 打开请求直达本地对话，并要求应用前台激活。最近任务 JSON 增加可选的 `latest_session_id`，旧缓存仍可解码。仅 Codex App 使用深链；工具名称、缺失/非法 ID 和系统打开失败回退到应用，其他 CLI 保持宿主级跳转。会话失效后的提示由 Codex 处理，不创建新任务。

单条通知将 ID 随负载保存，历史清理后仍有目标；旧通知可从对应事件找回会话 ID。批量通知保持记录入口，配额通知不指定会话，已读范围与之前一致。

验证：91 项 Swift 测试通过；原生深链 ID/CLI 分流、通知目标/已读范围、24 个界面截图场景及 8 个键盘导航场景通过。实际采集 JSON 已包含合法的 Codex 最近会话 ID。构建 121 使用原 Lingmou Local 证书安装；实机灵眸显示「打开这条 Codex 对话」提示。当前 Computer Use 工具禁止访问 Codex 自身窗口，因此未执行 Codex 窗口的端到端目视跳转验收，也未通过替代 UI 自动化绕过限制。
