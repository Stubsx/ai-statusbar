# 任务信号与跳转支持矩阵

以下是当前实现范围。检测到工具不代表它支持所有事件；「设置 → 工具与连接」显示同一份能力声明。各工具的专属开关、空闲时长与连接状态集中在对应工具下；统一的账号配额查询也在此页。Kimi Code 的跳转开关与 Kimi Work 的月度额度授权分别归入各自分区；工具未运行时仍可配置。通用页保留外观、启动更新与统一状态规则，数量单位位于「数据」页。现有配置值保持不变。

| 工具 | 明确本轮结束 | 明确中断 | 等待回答 | 等待权限 | 跳转层级 |
| --- | --- | --- | --- | --- | --- |
| Codex App / CLI | task_complete | turn_aborted | 未返回 request_user_input | 暂不支持 | App 本地对话深链 / CLI 宿主终端或编辑器 |
| Claude Code | assistant.stop_reason=end_turn | 暂不支持 | 暂不支持 | 暂不支持 | 宿主终端或编辑器 |
| ZCode | turn_usage.status=completed | error / cancelled | 暂不支持 | 暂不支持 | App，CLI 宿主兜底 |
| Kimi Code | 主代理 step.end.finishReason=end_turn，且无未闭合子代理 | 暂不支持 | 暂不支持 | 暂不支持 | 优先 Kimi Code App（应用内选择会话）；回退 Web 会话 / 宿主 |
| Kimi Work | 同 Kimi Code | 暂不支持 | 暂不支持 | 暂不支持 | App |
| Hermes | 无有效租约，且末条 assistant 明确 stop/end_turn/length | 明确 error/agent_error/content_filter | 暂不支持 | 暂不支持 | 已运行应用或宿主 |
| DSH | 暂不支持 | 暂不支持 | 暂不支持 | 暂不支持 | 本机默认 3080 端口 Web 页面 |

Kimi Code 的工具名称、会话行和通知点击优先打开已安装的 Kimi Code 桌面版，按 `com.kimi.code.desktop` 识别，与 Kimi Work 分开。复用运行实例并恢复窗口；未安装或系统启动失败时回退到下述 Web／宿主路径。当前核验的桌面版 1.0.1 只接受 `kimi-code://auth/success` 登录回调，没有官方会话深链。默认仅打开应用；设置「工具与连接 → Kimi Code → 桌面版精确跳转（实验性）」开启后，可通过本机调试连接切到指定会话。首次开启需退出 Kimi Code，再从灵眸打开以建立连接；不会自动重启运行中的应用。连接不可用、版本不兼容、会话不存在或无法核验时，仅打开应用。关闭开关会停止灵眸使用连接，但需退出 Kimi Code 并正常启动，调试端口才会关闭。

Kimi Code 的任务与最近任务携带会话 ID。回退网页时在后台读取 `~/.kimi-code/server/instances/`，核验心跳、实际可执行文件、进程启动时间及监听端口，然后请求本机 `/api/v1/healthz`、会话元数据和连接订阅。只有服务明确报告该会话正在运行、等待交互或已被网页客户端订阅时，才直接打开该实例的 `/sessions/{id}`；多个确认位置提供选择。只有历史记录、无法确认原位置时，显示「在网页查看」和「打开宿主终端」；服务未授权、会话不存在或接口不可用时明确反馈，不自动恢复 CLI、启动服务或发送提示词。网页打开可能在服务中加载已有会话。跳转浏览器时优先复用已打开的同源标签页（设置「工具与连接 → Kimi Code → 网页跳转复用标签页」，默认开启）：目标会话页已精确打开就直接聚焦，否则把最前面的同源标签导航到目标会话；浏览器未运行、不支持脚本接口（Chromium 系与 Safari 之外）、未授予浏览器自动化授权、超时或两次枚举间窗口序变化时，静默回落为照常新开标签页，绝不动别的标签页。浏览器未连接时走 Kimi 自身的认证页面。终端标签精确定位和 iTerm / VS Code 增强连接尚未接入。 当默认 Chromium 浏览器同时有开发工具启动的无界面实例时，若能唯一识别普通默认配置实例，通过浏览器自身的单实例机制把链接交给它，避免被后台测试进程接走；不猜测自定义配置目录。

所有工具保留已有活动状态与用量统计。不支持明确事件的工具会在完整快照持续三轮、至少约 30 秒停止活动后记录「暂无新活动」，不庆祝、不声称成功，不进入未读提醒。工具离线、缺失、采集失败或不完整快照不会推进结束推断。明确结束表示「本轮已结束，可查看结果」，不判断产出是否正确。

Kimi Code 桌面版按 `Kimi Code.app` 的主程序完整可执行文件后缀识别在线状态，不要求另有 `kimi`／`kimi-code` 命令行进程，排除 Helper、崩溃上报进程及 Kimi Work。桌面版与 CLI／Web 共用会话日志：提交后的待处理请求或未闭合模型步骤均算运行中，因此思考期间没有文字或工具输出也会保持运行；明确结束后恢复空闲，主程序退出后不再以残留日志维持运行。仅打开应用不会被判为忙碌，仍保留会话日志的过期限制。

Kimi Code 的本机 Web 模式与终端模式共用会话日志检测，新建项目和恢复历史会话均适用。Web 服务将进程标题改写为 `kimi-cod` 时，采集器读取 `~/.kimi-code/server/instances/*.json`，校验 30 秒内的心跳、PID、真实 Kimi 可执行文件及启动时间（允许 5 秒登记延迟），并对同一进程去重；仅服务在线不会判为忙碌，仍需近期主代理或子代理日志中存在未闭合工作。此检测不访问 Web API、不读取访问令牌。会话定位与浏览器跳转仍受上表限制。

菜单栏采用单色灵眸图标与运行任务总数，未读事件或读取异常以小角标提示，悬停可查看分工具状态。下拉菜单与桌面面板共用按 Harness 分组的会话列表，每组同时展示当前会话和最近结果，其余会话放在本组子菜单中；空闲或已退出的工具有记录时仍展示。未读会话以小圆点标记。桌面面板入口、显示模式、置顶与全屏隐藏统一位于「桌面显示」子菜单。

原生 App 的工具名称、会话行、菜单与通知共用跳转路由。工具名称打开应用或宿主，会话行携带具体会话 ID；不支持直达时按已有路由打开应用或宿主，提示中说明目标。已运行的 App 或宿主通过系统重开请求恢复窗口并切到前台，复用原应用实例，不额外申请辅助功能权限。从浮球或桌宠右键选择「打开面板」可获得键盘焦点。状态、用量、活跃、配额四页统一宽 380 点，切换时宽度不变，状态、用量、活跃页内容区域最高 320 点、配额页最高 480 点，所有 Harness 在同一滚动区域展示。每组直接平铺运行中的会话与尚未查看的新结果，等待处理的会话优先；数量多时在面板内纵向滚动，不再折叠会话。组标题、浮球、桌宠及菜单栏统一按同一份去重会话列表统计运行数和待查看数。每行显示状态、未读圆点，悬停高亮并显示跳转箭头，长标题单行省略且提示显示全文。相同 Harness 下同一会话的多轮事件合并为一行，采用最新状态和标题；重新运行时以当前运行态覆盖旧结果。明确结束显示「已结束」，中断和异常单独标注；暂无活动、已解除等待和已读历史不展示，不再用最近一条对话补位。未查看的结果保留到点开原对话，即使工具已退出也可查看。看板只保留「状态、用量、活跃、配额」四页，顶部按钮直接平铺在原生横向滚动区域中，按钮为 42 × 24 点，一次露出约三个半按钮，仅在还有内容的边缘显示磨砂玻璃模糊与渐隐过渡，支持触控板左右滑动和横向滚轮；点击按钮直接切换，选中项会自动滚入可见范围。最近事件、运行详情及全部会话页均已移除。⌘1–⌘4 直接切换四页，Esc 返回状态；旧版 ⌘5、⌘E 不再打开已删除页面。普通打开面板恢复上次页面；旧版保存的最近事件或详情页迁移到状态页。「清空会话记录」移至设置的「数据」页，仍只清理本机历史并保留运行和等待会话。键盘操作期间不会因鼠标离开而自动收回。Codex App 的当前任务、最近任务、历史事件与单条通知携带会话 ID 时，使用官方 `codex://threads/<thread-id>` 直达本地对话；工具名称、缺失或非法 ID 退回应用级激活，CLI 保持宿主跳转。系统未接受深链时也退回应用；目标对话已删除或不可访问时由 Codex 显示其结果，不自动新建任务。批量通知打开按 Harness 分组的状态页，不任意选择一条对话。Kimi Code 按上文优先打开桌面版，再回退 Web 会话或宿主，其余工具按宿主能力跳转。多个宿主应用提供选择；只有一个宿主时直接切过去，同宿主多个会话的具体窗口或标签仍需在应用内选择。Kimi 的 kimi-code 运行时和常见 Python/Node 包装进程也参与宿主识别。后台服务、脱离终端的 tmux、宿主退出、非默认 DSH 端口需要手动打开原工具。

点击面板或菜单中的会话，会清除该行所包含事件的未读提醒，并打开原工具；已读结果从列表移除，仍在运行的会话保留，本机历史不删除。点击后才到达的新事件和其他会话的提醒不受影响。等待事件的已读与任务是否仍在等待互相独立，查看提醒不会替用户回答或确认。相同事件再次采集或重启不会恢复为未读，新事件仍会正常提醒。单条系统通知直达原工具时按其携带的事件 ID 标记已读；批量通知只打开状态列表，结果保留到逐条查看，配额通知不会清除任务事件。

健康状态区分未检测、未运行、运行但无数据、正常、源数据读取失败。检查来源根目录和主要数据库/JSON；不能保证识别每个上游版本的局部字段变更。空白新会话和未知事件不视为损坏；彻底不可解析的近期日志会显示错误。配额登录提示仅在来源明确报登录/凭据缺失时显示；普通请求失败显示暂不可用。

状态超过 45 秒未更新会标记；配额快照保鲜期按窗口长度分级：月窗 24 小时、周窗 12 小时、小时级窗口 1 小时。Kimi Code 等工具在发送消息后才会刷新 token 恢复更新；读取失败但有未过期的历史快照时，配额卡片展示快照——进度条降饱和并标注「快照 · 更新于 X 前，可能不是最新」，附带读取失败原因（如有）。登录失效或在线配额关闭时不展示快照；从未读到或窗口全部过期时显示「当前额度暂不可用」、读取原因及设置入口，曾有有效窗口时注明上次成功读取时间。失败请求的时间不当作成功更新时间。超出保鲜期的过期配额不触发提醒，缓存仍保留供后续恢复使用。同步摘要统计超过 1 小时未更新的设备；各设备时间在设置中单独列出。同步目录不可用时显示本机统计。

自动测试用脱敏 fixture 验证事件语义，不需要登录第三方工具。工具真实环境和窗口组合依赖用户已有运行环境；未运行的工具不自动启动任务、申请权限或模拟真实通知。

原生 App 由本地文件变化触发任务状态采集（合并频繁写入，至多每秒启动一轮），数据库及 WAL 每 0.5 秒只检查文件属性，5 秒完整状态轮询兜底，每 30 秒独立更新用量与配额；联网失败不会阻塞任务状态。其他前端仍按各自刷新频率复用完整 JSON。事件立即写入历史，开启合并通知时最多合并约 1 秒，等待回答仍即时通知。小于采样间隔的任务可能看不到中间忙碌态；明确结束事件仍可补获。
