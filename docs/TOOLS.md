# 任务信号与跳转支持矩阵

以下是当前实现范围。检测到工具不代表它支持所有事件；「连接与诊断」显示同一份能力声明。

| 工具 | 明确本轮结束 | 明确中断 | 等待回答 | 等待权限 | 跳转层级 |
| --- | --- | --- | --- | --- | --- |
| Codex App / CLI | task_complete | turn_aborted | 未返回 request_user_input | 暂不支持 | App 本地对话深链 / CLI 宿主终端或编辑器 |
| Claude Code | assistant.stop_reason=end_turn | 暂不支持 | 暂不支持 | 暂不支持 | 宿主终端或编辑器 |
| ZCode | turn_usage.status=completed | error / cancelled | 暂不支持 | 暂不支持 | App，CLI 宿主兜底 |
| Kimi Code | 主代理 step.end.finishReason=end_turn，且无未闭合子代理 | 暂不支持 | 暂不支持 | 暂不支持 | 已确认的 Web 会话链接 / 历史位置选择 / 宿主终端或编辑器 |
| Kimi Work | 同 Kimi Code | 暂不支持 | 暂不支持 | 暂不支持 | App |
| Hermes | 无有效租约，且末条 assistant 明确 stop/end_turn/length | 明确 error/agent_error/content_filter | 暂不支持 | 暂不支持 | 已运行应用或宿主 |
| DSH | 暂不支持 | 暂不支持 | 暂不支持 | 暂不支持 | 本机默认 3080 端口 Web 页面 |

Kimi Code 的任务与最近任务携带会话 ID。点击时在后台读取 `~/.kimi-code/server/instances/`，核验心跳、实际可执行文件、进程启动时间及监听端口，然后请求本机 `/api/v1/healthz`、会话元数据和连接订阅。只有服务明确报告该会话正在运行、等待交互或已被网页客户端订阅时，才直接打开该实例的 `/sessions/{id}`；多个确认位置提供选择。只有历史记录、无法确认原位置时，显示「在网页查看」和「打开宿主终端」；服务未授权、会话不存在或接口不可用时明确反馈，不自动恢复 CLI、启动服务或发送提示词。网页打开可能在服务中加载已有会话，浏览器可能新开标签；当前不保证复用原标签。浏览器未连接时走 Kimi 自身的认证页面。终端标签精确定位和 iTerm / VS Code 增强连接尚未接入。 当默认 Chromium 浏览器同时有开发工具启动的无界面实例时，若能唯一识别普通默认配置实例，通过浏览器自身的单实例机制把链接交给它，避免被后台测试进程接走；不猜测自定义配置目录。

所有工具保留已有活动状态与用量统计。不支持明确事件的工具会在完整快照持续三轮、至少约 30 秒停止活动后记录「暂无新活动」，不庆祝、不声称成功，不进入未读提醒。工具离线、缺失、采集失败或不完整快照不会推进结束推断。明确结束表示「本轮已结束，可查看结果」，不判断产出是否正确。

Kimi Code 的本机 Web 模式与终端模式共用会话日志检测，新建项目和恢复历史会话均适用。Web 服务将进程标题改写为 `kimi-cod` 时，采集器读取 `~/.kimi-code/server/instances/*.json`，校验 30 秒内的心跳、PID、真实 Kimi 可执行文件及启动时间（允许 5 秒登记延迟），并对同一进程去重；仅服务在线不会判为忙碌，仍需近期主代理或子代理日志中存在未闭合工作。此检测不访问 Web API、不读取访问令牌。会话定位与浏览器跳转仍受上表限制。

菜单栏采用单色灵眸图标与运行任务总数，未读事件或读取异常以小角标提示，悬停可查看分工具状态。下拉菜单优先显示运行中的工具和任务：每个工具直接展示前三项，其余任务在子菜单中逐项跳转；空闲工具集中收纳。桌面面板入口、显示模式、置顶与全屏隐藏统一位于「桌面显示」子菜单，最近事件仍可通过 ⌘2 打开。

原生 App 的工具名称、任务行、菜单与通知共用跳转路由。状态栏菜单中的工具名称可直接点击；已运行的 App 或宿主通过系统重开请求恢复窗口并切到前台，复用原应用实例。隐藏与最小化窗口由目标应用处理系统重开事件，不额外申请辅助功能权限。从浮球或桌宠右键选择「打开面板」可获得键盘焦点。状态速览宽 300 点，最多显示 4 个工具（有提醒或采集异常时最多 3 个）和一条优先提醒。支持会话跳转的工具默认展示前三条当前会话，可在原处展开其余会话；无当前会话时可显示一条可跳转的最近会话。内容区域最高 320 点，更多内容在面板内滚动。工具标题只打开应用或宿主；会话行仅在支持直达且 ID 有效时成为按钮，悬停显示浅色高亮和右上箭头，长标题单行省略并通过提示显示全文。不能直达的工具保持一条当前任务预览，会话文字没有 Hover 或点击动作，通过工具标题打开应用；运行详情使用相同规则。Kimi 会话按钮只在发现有效的本机 Web 服务时显示，具体目标仍由点击时的路由检查决定。右上角菜单可打开用量、活跃、配额、记录或完整运行详情；⌘1–⌘5 切换页面，⌘E 查看运行详情或返回速览，Esc 返回速览。普通点击浮球、桌宠或菜单「桌面显示 → 打开桌面面板」时恢复上次使用的页面，重启应用后也保留；首次打开默认速览。显式的用量、最近事件入口仍直达对应页面，并成为下次恢复的页面。键盘操作期间不会因鼠标离开而自动收回。Codex App 的当前任务、最近任务、历史事件与单条通知携带会话 ID 时，使用官方 `codex://threads/<thread-id>` 直达本地对话；工具名称、缺失或非法 ID 退回应用级激活，CLI 保持宿主跳转。系统未接受深链时也退回应用；目标对话已删除或不可访问时由 Codex 显示其结果，不自动新建任务。批量通知仍打开记录，不任意选择一条对话。Kimi Code 按上文的 Web 会话能力跳转，其余工具按宿主能力跳转。多个宿主应用提供选择；只有一个宿主时直接切过去，同宿主多个会话的具体窗口或标签仍需在应用内选择。Kimi 的 kimi-code 运行时和常见 Python/Node 包装进程也参与宿主识别。后台服务、脱离终端的 tmux、宿主退出、非默认 DSH 端口需要手动打开原工具。

点击速览或历史中的事件会立即标记已读、清除该条提醒和角标，并打开原工具；历史记录保留。等待事件的已读与任务是否仍在等待互相独立，查看提醒不会替用户回答或确认。相同事件再次采集或重启不会恢复为未读，新事件仍会正常提醒。系统通知也按其携带的事件 ID 标记已读；打开批量通知只影响该批次，配额通知不会清除任务事件。

健康状态区分未检测、未运行、运行但无数据、正常、源数据读取失败。检查来源根目录和主要数据库/JSON；不能保证识别每个上游版本的局部字段变更。空白新会话和未知事件不视为损坏；彻底不可解析的近期日志会显示错误。配额登录提示仅在来源明确报登录/凭据缺失时显示；普通请求失败显示暂不可用。

状态超过 45 秒未更新会标记；一般配额超过 10 分钟过期，Kimi Work 因上游一小时缓存允许 70 分钟。过期配额不提醒。同步摘要统计超过 1 小时未更新的设备；各设备时间在设置中单独列出。同步目录不可用时显示本机统计。

自动测试用脱敏 fixture 验证事件语义，不需要登录第三方工具。工具真实环境和窗口组合依赖用户已有运行环境；未运行的工具不自动启动任务、申请权限或模拟真实通知。

原生 App 由本地文件变化触发任务状态采集（合并频繁写入，至多每秒启动一轮），数据库及 WAL 每 0.5 秒只检查文件属性，5 秒完整状态轮询兜底，每 30 秒独立更新用量与配额；联网失败不会阻塞任务状态。其他前端仍按各自刷新频率复用完整 JSON。事件立即写入历史，开启合并通知时最多合并约 1 秒，等待回答仍即时通知。小于采样间隔的任务可能看不到中间忙碌态；明确结束事件仍可补获。
