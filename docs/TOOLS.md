# 任务信号与跳转支持矩阵

以下是当前实现范围。检测到工具不代表它支持所有事件；「连接与诊断」显示同一份能力声明。

| 工具 | 明确本轮结束 | 明确中断 | 等待回答 | 等待权限 | 跳转层级 |
| --- | --- | --- | --- | --- | --- |
| Codex App / CLI | task_complete | turn_aborted | 未返回 request_user_input | 暂不支持 | App 本地对话深链 / CLI 宿主终端或编辑器 |
| Claude Code | assistant.stop_reason=end_turn | 暂不支持 | 暂不支持 | 暂不支持 | 宿主终端或编辑器 |
| ZCode | turn_usage.status=completed | error / cancelled | 暂不支持 | 暂不支持 | App，CLI 宿主兜底 |
| Kimi Code | 主代理 step.end.finishReason=end_turn，且无未闭合子代理 | 暂不支持 | 暂不支持 | 暂不支持 | 宿主终端或编辑器 |
| Kimi Work | 同 Kimi Code | 暂不支持 | 暂不支持 | 暂不支持 | App |
| Hermes | 无有效租约，且末条 assistant 明确 stop/end_turn/length | 明确 error/agent_error/content_filter | 暂不支持 | 暂不支持 | 已运行应用或宿主 |
| DSH | 暂不支持 | 暂不支持 | 暂不支持 | 暂不支持 | 本机默认 3080 端口 Web 页面 |

所有工具保留已有活动状态与用量统计。不支持明确事件的工具会在完整快照持续三轮、至少约 30 秒停止活动后记录「暂无新活动」，不庆祝、不声称成功，不进入未读提醒。工具离线、缺失、采集失败或不完整快照不会推进结束推断。明确结束表示「本轮已结束，可查看结果」，不判断产出是否正确。

菜单栏采用单色灵眸图标与运行任务总数，未读事件或读取异常以小角标提示，悬停可查看分工具状态。下拉菜单优先显示运行中的工具和任务：每个工具直接展示前三项，其余任务在子菜单中逐项跳转；空闲工具集中收纳。桌面面板入口、显示模式、置顶与全屏隐藏统一位于「桌面显示」子菜单，最近事件仍可通过 ⌘2 打开。

原生 App 的工具名称、任务行、菜单与通知共用跳转路由。状态栏菜单中的工具名称可直接点击；已运行的 App 或宿主通过系统重开请求恢复窗口并切到前台，复用原应用实例。隐藏与最小化窗口由目标应用处理系统重开事件，不额外申请辅助功能权限。从浮球或桌宠右键选择「打开面板」可获得键盘焦点。默认只显示最多 4 个工具（有提醒或采集异常时最多 3 个）、每个工具的一条当前任务和一条优先提醒。右上角菜单可打开用量、活跃、配额、记录或完整运行详情；⌘1–⌘5 切换页面，⌘E 查看运行详情或返回速览，Esc 返回速览。普通点击浮球、桌宠或菜单「桌面显示 → 打开桌面面板」时恢复上次使用的页面，重启应用后也保留；首次打开默认速览。显式的用量、最近事件入口仍直达对应页面，并成为下次恢复的页面。键盘操作期间不会因鼠标离开而自动收回。Codex App 的当前任务、最近任务、历史事件与单条通知携带会话 ID 时，使用官方 `codex://threads/<thread-id>` 直达本地对话；工具名称、缺失或非法 ID 退回应用级激活，CLI 保持宿主跳转。系统未接受深链时也退回应用；目标对话已删除或不可访问时由 Codex 显示其结果，不自动新建任务。批量通知仍打开记录，不任意选择一条对话。其他工具仍按下述宿主能力跳转。多个宿主应用提供选择；只有一个宿主时直接切过去，同宿主多个会话的具体窗口或标签仍需在应用内选择。Kimi 的 kimi-code 运行时和常见 Python/Node 包装进程也参与宿主识别。后台服务、脱离终端的 tmux、宿主退出、非默认 DSH 端口需要手动打开原工具。

点击速览或历史中的事件会立即标记已读、清除该条提醒和角标，并打开原工具；历史记录保留。等待事件的已读与任务是否仍在等待互相独立，查看提醒不会替用户回答或确认。相同事件再次采集或重启不会恢复为未读，新事件仍会正常提醒。系统通知也按其携带的事件 ID 标记已读；打开批量通知只影响该批次，配额通知不会清除任务事件。

健康状态区分未检测、未运行、运行但无数据、正常、源数据读取失败。检查来源根目录和主要数据库/JSON；不能保证识别每个上游版本的局部字段变更。空白新会话和未知事件不视为损坏；彻底不可解析的近期日志会显示错误。配额登录提示仅在来源明确报登录/凭据缺失时显示；普通请求失败显示暂不可用。

状态超过 45 秒未更新会标记；一般配额超过 10 分钟过期，Kimi Work 因上游一小时缓存允许 70 分钟。过期配额不提醒。同步摘要统计超过 1 小时未更新的设备；各设备时间在设置中单独列出。同步目录不可用时显示本机统计。

自动测试用脱敏 fixture 验证事件语义，不需要登录第三方工具。工具真实环境和窗口组合依赖用户已有运行环境；未运行的工具不自动启动任务、申请权限或模拟真实通知。

原生 App 由本地文件变化触发任务状态采集（合并频繁写入，至多每秒启动一轮），数据库及 WAL 每 0.5 秒只检查文件属性，5 秒完整状态轮询兜底，每 30 秒独立更新用量与配额；联网失败不会阻塞任务状态。其他前端仍按各自刷新频率复用完整 JSON。事件立即写入历史，开启合并通知时最多合并约 1 秒，等待回答仍即时通知。小于采样间隔的任务可能看不到中间忙碌态；明确结束事件仍可补获。
