# 常驻能耗优化验证

2026-09-16，macOS 本机，晴蓝悬浮球显示工作状态、详情面板收起。

## 改动

- 晴蓝／水墨工作光环保持原有绘制、尺寸和周期，旋转交给原生 Core Animation 层。隐藏／遮挡时暂停，恢复后从原相位继续；减少动态效果时显示静态图。AppKit 会重置视图 backing layer 的锚点，因此旋转矩阵显式围绕中心构造。
- 鼠标静止时每 0.25 秒检查一次位置；眼睛移动收敛和眨眼期间仍按 30fps 更新。隐藏后停止，减少动态效果时使用低频采样。首次响应鼠标移动最多多等待约 0.25 秒，另加系统定时器容差。
- 文件变化触发的状态扫描重置 5 秒兜底期限，避免原来的固定周期紧接着再扫描；手动扫描取消已排队的同类扫描。仍保留文件事件的每秒合并上限、数据库 WAL 检查和 30 秒统计刷新。
- 面板收起时跳过强制测量和窗口尺寸调整，展开或从全屏恢复时补做；外观、全屏兜底计时器增加少量容差，方便系统合并唤醒。
- 常驻活动改为允许系统自动休眠的选项；仍保留任务监测所需的 App Nap 豁免。
- 日志 ISO8601 时间解析复用格式化器，并通过锁保护并发读取。

## 验证

- Swift 采集回归 121 项通过，包含 busy／idle／off 转换、时间格式混用和并发解析。
- 原生刷新回归：文件事件发生在旧兜底周期之前时只增加一次扫描；其后无文件变化时仍继续执行兜底扫描。
- 真实 NSApplication 事件循环检查两种光环的呈现层旋转、固定中心、隐藏／恢复、指针穿透；水墨／晴蓝缓存流动、悬停、休息和减少动态效果检查通过。
- 指针回归：静止采样约 4Hz，移动仍平滑跟随，减少动态效果降频，隐藏后没有位置读取，重新显示后恢复。
- 原生界面快照、通知与本地事件链路、权限及开源检查通过。修正了界面测试夹具遗漏 `MaintenanceStore` 参数导致的编译问题。

## 测量口径与限制

优化前主进程在 3 个约 5 秒窗口中的 CPU 为 4.9%、6.0%、4.8%；安装后的 4 个窗口为 2.8%、1.9%、1.9%、2.2%。两次都是晴蓝工作态、面板收起，真实任务数量在变化，因此属于现场短时观察而非固定负载的严格 A/B。这些值只包含主进程，不包含短命采集子进程及 WindowServer，不能换算为整机省电比例。

优化前 `pmset -g assertions` 列出了灵眸的 `PreventUserIdleSystemSleep`；安装后已没有灵眸的这一声明。通用 arm64／x86_64 本机安装版为 1.3.0 build 128，签名验证通过，已重启；安装版 JSON 仍包含 8 个工具及原有状态／统计字段。通过真实界面截屏核对了工作态悬浮球外观。

交替执行新旧采集器各 5 次，单次扫描的 CPU 时间中位数分别约 0.48／0.45 秒；本次现场样本没有证明单轮采集成本下降。日志、任务和其他应用仍在活动，未进行固定输入的长期电量对照。本轮主要减少持续界面动画、鼠标轮询和重复扫描，并消除灵眸自身的阻止自动休眠声明。

原始性能采样保存在 Git 忽略的 `output/energy/`，不纳入版本库。
