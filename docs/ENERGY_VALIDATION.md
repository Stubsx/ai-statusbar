# 常驻能耗优化验证

2026-09-16，macOS 本机，晴蓝悬浮球显示工作状态、详情面板收起。

## 改动

- 晴蓝／水墨工作光环保持原有绘制、尺寸和周期，旋转交给原生 Core Animation 层。隐藏／遮挡时暂停，恢复后从原相位继续；减少动态效果时显示静态图。AppKit 会重置视图 backing layer 的锚点，因此旋转矩阵显式围绕中心构造。
- 鼠标静止时每 0.25 秒检查一次位置；眼睛移动收敛和眨眼期间仍按 30fps 更新。隐藏后停止，减少动态效果时使用低频采样。首次响应鼠标移动最多多等待约 0.25 秒，另加系统定时器容差。
- 文件变化触发的状态扫描重置 5 秒兜底期限，避免原来的固定周期紧接着再扫描；手动扫描取消已排队的同类扫描。仍保留文件事件的每秒合并上限、数据库 WAL 检查和 30 秒统计刷新。
- 面板收起时跳过强制测量和窗口尺寸调整，展开或从全屏恢复时补做；外观、全屏兜底计时器增加少量容差，方便系统合并唤醒。
- 常驻活动改为允许系统自动休眠的选项；仍保留任务监测所需的 App Nap 豁免。
- 日志 ISO8601 时间解析复用格式化器，并通过锁保护并发读取。

## 验证

- Swift 采集回归 121 项通过，包含 busy／idle／off 转换、时间格式混用和并发解析。
- 原生刷新回归：文件事件发生在旧兜底周期之前时只增加一次扫描；其后无文件变化时仍继续执行兜底扫描。
- 真实 NSApplication 事件循环检查两种光环的呈现层旋转、固定中心、隐藏／恢复、指针穿透；水墨／晴蓝缓存流动、悬停、休息和减少动态效果检查通过。
- 指针回归：静止采样约 4Hz，移动仍平滑跟随，减少动态效果降频，隐藏后没有位置读取，重新显示后恢复。
- 原生界面快照、通知与本地事件链路、权限及开源检查通过。修正了界面测试夹具遗漏 `MaintenanceStore` 参数导致的编译问题。

## 测量口径与限制

优化前主进程在 3 个约 5 秒窗口中的 CPU 为 4.9%、6.0%、4.8%；安装后的 4 个窗口为 2.8%、1.9%、1.9%、2.2%。两次都是晴蓝工作态、面板收起，真实任务数量在变化，因此属于现场短时观察而非固定负载的严格 A/B。这些值只包含主进程，不包含短命采集子进程及 WindowServer，不能换算为整机省电比例。

优化前 `pmset -g assertions` 列出了灵眸的 `PreventUserIdleSystemSleep`；安装后已没有灵眸的这一声明。通用 arm64／x86_64 本机安装版为 1.3.0 build 128，签名验证通过，已重启；安装版 JSON 仍包含 8 个工具及原有状态／统计字段。通过真实界面截屏核对了工作态悬浮球外观。

交替执行新旧采集器各 5 次，单次扫描的 CPU 时间中位数分别约 0.48／0.45 秒；本次现场样本没有证明单轮采集成本下降。日志、任务和其他应用仍在活动，未进行固定输入的长期电量对照。本轮主要减少持续界面动画、鼠标轮询和重复扫描，并消除灵眸自身的阻止自动休眠声明。

原始性能采样保存在 Git 忽略的 `output/energy/`，不纳入版本库。

## 2026-09-17：低能耗模式与视线跟随

- 在「设置 → 通用」新增「低能耗模式」，默认关闭并通过本机偏好设置记忆。开启后晴蓝／水墨均使用缓存静帧，移除流动与工作光环的播放视图，保留视线跟随、眨眼和状态提示；关闭后恢复动画。以此模式启动时不会请求生成循环帧。
- 视线和眨眼状态移入独立脸部视图，避免逐帧更新球体、光环及数字胶囊。活动期间按 60fps 调度，并按经过时间平滑收敛；静止仍以 4Hz 检查指针，隐藏后停止。首次移动仍可能等待约 0.25 秒的静止检测间隔。
- 流动、工作环和眼睛同时观察窗口可见性与遮挡通知，修复跨空间悬浮窗隐藏后遮挡标记未及时改变时继续播放的问题。
- 原生事件循环检查已覆盖低能耗启动、两种配色、运行中开关、恢复流动、保留眼睛跟随、系统减少动态效果及隐藏／恢复；静态绘制与方向几何检查通过。

本轮验证的是动画与刷新行为，尚未在出现卡顿的其他电脑上测量帧率或整机功耗，不据此承诺固定的节能比例。

## 2026-09-18：跟随唤醒与原生眼睛

- 可见浮球通过鼠标移动／拖动事件立即唤醒跟随，静止时保留 4Hz 位置探测作为兜底。仅使用当前位置，不监听按键、不记录轨迹、不申请新权限；隐藏时撤销监听。低能耗模式也使用同一套眼睛跟随。
- 按真实指针活动判断是否保持高频，移动结束后保留 0.5 秒收敛时间，避免“眼睛接近目标”导致缓慢移动时反复降到 4Hz。高报告率输入只唤醒一次，持续采样交给显示时钟。
- 眼睛和眨眼直接修改两个原生 CALayer，不再通过 SwiftUI 状态触发布局。macOS 14 及以上使用所在视图的显示时钟；macOS 12／13 使用 Core Video 显示时钟并合并主线程回调，目标频率不超过 60Hz。只有显示时钟不可用时才退回重复定时器；切换屏幕后重建时钟。
- 活动期间按实际经过时间追赶当前位置，不再把长帧间隔截断为 1/30 秒。空闲唤醒使用一帧的初始步长，避免把整个空闲间隔当作动画时间而突然跳转。
- 原生回归覆盖立即唤醒、1000 次输入唤醒合并、远处每秒 1 点的缓慢移动、静止降频、隐藏输入、恢复与销毁。约 0.85 秒慢速移动样本中，位置采样约 60Hz，p95 与最大间隔约 16.7ms；这些是本机采样回调间隔，不等同于显示器实际呈现帧率。
- 单独运行 Core Video 路径，在主线程人为阻塞 120ms 后验证只保留有限回调，停止后不再投递，重启正常。两种浮球风格、低能耗开关、减少动态效果、原生界面快照与菜单／通知回归均通过。

本机验证不能替代目标低配置电脑的实际流畅度和功耗测试。本轮没有新的长期整机功耗对照；不宣称所有硬件始终达到 60fps。验证输出位于 Git 忽略的 `output/floating-ball/gaze-*.log` 和 `low-energy-live-gaze.png`。

## 2026-09-18：流动与光圈停播恢复

- 用户补充故障环境为 M4、macOS 26，且低能耗模式与系统减少动态效果均关闭，因此不能将持续静止简单归因于硬件性能。M4 Pro／macOS 26.6.2 上正常播放基线通过；尚未直接采集到报告故障电脑上的原生图层状态。
- 故障注入确认旧实现的恢复缺口：移除可见浮球的流动、光圈动画后，没有业务状态或可见性变化就不会重新启动。仅检查动画对象存在，也不能发现图层时钟已停住。
- 播放期间每秒检查一次实际呈现进度，补回被移除的动画；连续两次检查没有进展时，改为最多 30fps 的原生图层更新，按单调时钟保持原循环速度与相位。正常机器继续由 Core Animation 播放。只有异常时启用备用计时器，这条兼容路径比正常原生播放增加主线程唤醒，不宣称能耗更低。
- 流动先准备 24 帧、112px 的轻量完整循环，再无缝替换为 96 帧、160px 的完整循环，减少冷启动等待。后台回调只接收缓存，已销毁的视图不会被重新启动。
- 在真实 NSApplication 事件循环中验证：动画被移除后自动恢复；动画仍存在但图层时钟被强制暂停后，备用路径确实产生不同的呈现帧与旋转角度；休息、隐藏、恢复和销毁均正确管理计时器。两种配色、低能耗模式、减少动态效果与眼睛跟随回归仍通过。

故障注入证明上述恢复路径有效，不代表已确认目标电脑上导致系统图层停播的具体触发条件。对照输出保存在 Git 忽略的 `output/floating-ball/compat-reproduction.log` 与 `compat-*.log`。
