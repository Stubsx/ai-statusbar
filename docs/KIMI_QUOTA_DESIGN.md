# Kimi Work 额度连接与授权

保留 Kimi Work 的任务监测、月度额度、分项用量和套餐显示。任务监测读取本地会话库及 wire 事件；额度查询是独立的慢速通路。额度权限不足不能打断任务监测，也不能使定时刷新反复打开系统授权窗口。

## 问题与修复

旧采集器通过 `SecItemCopyMatching` 读取 Electron safeStorage 的口令，却未禁止交互。未授权的定时采集因此可能停在钥匙串窗口；结束采集进程后，下轮仍可再次申请。固定代码签名有助于系统识别程序，但不能替代拒绝、等待和权限失效时的控制逻辑。

- 后台同时通过 `LAContext.interactionNotAllowed` 和传统钥匙串的 `SecKeychainSetUserInteractionAllowed(false)` 禁止交互。Kimi 使用传统登录钥匙串，不能只依赖 Data Protection Keychain 的选项。禁用失败则不读取；读取后恢复进程原有状态。
- 用户在设置中选择「读取 Kimi 月度额度 → 连接并开启」，采集器才单独执行一次授权。已有权限时可直接成功。请求不参与定时任务，不输出口令或令牌。
- App 防止重复点击，进程间文件锁防止多个前端同时申请；请求自身 60 秒超时，App 另有子进程超时退出保护。拒绝、取消、超时都保持关闭，不自动重试。
- 授权成功后使权限失败缓存失效，保留最近一次有效额度。同时把口令备份到 `~/.ai-statusbar/kimi-safe-storage.key`（目录 0700、文件 0600）：钥匙串「始终允许」只认当次构建的程序哈希，重建或替换 App 后 ACL 必然失效，备份让授权真正持久；后台读取在钥匙串拒绝时回退到备份。关闭解密开关立即删除备份；Kimi 桌面端轮换口令后备份失效，重新授权一次即可，解密失败不会自动删除备份以免瞬时损坏丢授权。
- 原有月度额度接口、套餐和分项计算保留。没有新增常驻凭证服务或修改 Kimi 安装文件。

## 替代来源调查

本机 Kimi 安装包显示：其主进程调用 `GetSubscription` 和 `GetSubscriptionStats`，把订阅结果保存在运行时变量，并通过日志记录 `refreshed(sub)` 中的 `omniRatio` 与 `resetAt`。检查到的本地日志确实包含这两个字段，但摘要可数小时不更新，且没有现有分项展示需要的完整数据。

本次未验证到可供第三方稳定读取完整额度的公开本地接口。Electron 内部 IPC 不能直接视为公开接口。通过注入代码、开启调试端口或修改 Kimi 安装包复用其内存数据，会引入更高的维护成本，因此不采用。

本地摘要可作为后续补充来源，但需验证账号切换、日志轮换、格式变化和新鲜度，并明确标注更新时间。不能用其过期或缺失的字段冒充实时完整额度。当前先保留完整查询能力，修复授权生命周期。

## 验证范围

使用虚构凭证和替身系统调用验证：后台禁止交互、禁用失败时不读取、拒绝缓存、交互锁、授权后缓存失效；原生测试使用测试子进程验证超时退出、重复点击、拒绝和取消。测试不向真实钥匙串申请权限，也不写入厂商凭证。
